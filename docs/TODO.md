# Ossein

The purpose of this project is to build a macos binary that can run
linux containers inside a VM provided by macOS.

The first iteration (under v1-containerization) demonstrated feasibility
by leveraging apple/containerization.

However, the desire is to replace that entirely and instead build our own
on top of https://github.com/code-Hex/vz

> **Note, 2026-07-30 — networking replaced.** Everything below that describes
> gvisor-tap-vsock, `FileHandleNetworkDeviceAttachment`, `AcceptVfkit`, a
> socketpair wire, or a static `192.168.127.x` guest IP is HISTORY, kept as the
> record of what was built and why. The current design is
> `VZNATNetworkDeviceAttachment` — Virtualization.framework's own NAT on a
> dedicated host-local subnet — with a userspace DHCP client in vminitd
> (`guest/internal/guestagent/dhcp.go`) that acquires the lease and applies it
> over the netlink paths that already existed. That removed the userspace TCP/IP
> stack, 89 packages, ~6 MiB of binary, the logrus bridge, and `pkg/netstack`
> entirely. The vsock control plane is untouched and unrelated.

> **Note, 2026-07-30 — RPC transport replaced.** Everything below that describes
> `google.golang.org/grpc`, `protoc-gen-go-grpc`, a gRPC server in vminitd, or
> gRPC status codes on the host is HISTORY. The control plane now speaks
> [Connect](https://connectrpc.com) over plain HTTP/1.1 on the same vsock
> listener (`internal/sandbox/sandboxconnect`, generated by protoc-gen-connect-go
> pinned via a go tool directive). No h2c: the contract is unary plus one
> server-stream (`Copy`), which Connect carries over HTTP/1.1 chunked encoding —
> only bidi streaming would force HTTP/2. The proto, the vsock port, and the
> revision handshake are all unchanged.
>
> This did NOT shrink the binaries — measured `vminitd` 10.94 → 11.06 MiB and
> `ossein` 36.40 → 36.49 MiB, because `net/http`'s server path plus `crypto/tls`
> cost about what grpc's HTTP/2 stack cost. The win is dependency surface:
> third-party packages in `vminitd` fell from ~135 to 71 (grpc's 64 gone,
> `golang.org/x/net` 9 → 1, `genproto` and `x/text` gone entirely).

## Implementation plan

Status: **implemented and runtime-verified (2026-07-08).** Live on real
hardware: `doctor` (boot + vminitd handshake), `run -it alpine /bin/sh`
(interactive container, TTY), and the full buildkit path — `buildkit
-detach` → `buildctl build` of a real Dockerfile over the vsock-proxied
unix socket, with registry pulls through the embedded gvisor-tap-vsock
network. Bugs found live and fixed: vminitd requires
`containerID` on every process RPC (init = `id == containerID`);
Swift's `LinuxNamespace` decoder requires the `path` key (patched at
marshal); vminitd's own cgroup `memory.high=80MiB` throttles tmpfs
rootfs extraction to ~256KB/s (lifted via WriteFile RPC for the VM's
life); ProxyVsock `OUT_OF` (not `INTO`) is the expose-guest-socket
direction and guestPath is root-namespace (rootfs-prefixed); h2 servers
speak first, so the readiness probe must accept data-on-connect.
`--rosetta` (amd64 debian, x86-64 ELF executing via Rosetta) and
`--mount` (virtio-fs read + writeback) both verified live 2026-07-08.
Persistent per-project buildkit cache implemented and verified live
(2026-07-09): `internal/volume` creates + formats a sparse 4096-block
ext4 image (pure Go via go-diskfs `ext4.Create`, `SectorsPerBlock: 8` —
no `mkfs` in the initfs, verified absent), attaches it as virtio-blk
`/dev/vdb`, and mounts it at `/var/lib/buildkit` before buildkitd starts;
`Close` syncs+unmounts before VM stop so writes reach the host image.
Warm-cache-across-restart confirmed live (buildctl: cached RUN on the
second VM). `--cache` is central-by-default (keyed by CWD or a bare name,
under `DataDir()/buildkit/<hash>/`) with a project-local escape (a
path-like `--cache ./x` stores the image there + writes a `.gitignore`);
`--print-cache` reveals the resolved dir. Single-writer via flock with a
fail-fast pre-check; `gc --prune-cache` reclaims central volumes; `stop
--grace` (default 60s) covers the shutdown flush before SIGKILL. Still
unexercised: non-buildkit long-running services; distribution signing;
aqua packaging.
Build with:

```sh
just build
export OSSEIN_KERNEL=v1-containerization/.src/kernel/kernel-arm64
export OSSEIN_INITFS=v1-containerization/.src/bin/initfs.ext4
./build/ossein doctor            # M1 accept: boot + vminitd gRPC + tmpfs + teardown
./build/ossein run -it docker.io/library/alpine:3.22@sha256:14358309a308569c32bdc37e2e0e9694be33a9d99e68afb0f5ff33cc1f695dce /bin/sh   # M2+M3+M4
eval "$(./build/ossein buildkit -detach)" && buildctl debug workers  # M3 accept
./build/ossein stop                                            # tear down
```

Layout: `cmd/ossein` (CLI), `internal/vm` (Code-Hex/vz assembly),
`internal/guest` (+ generated `sandbox/` gRPC client), `internal/image`,
`internal/netstack`, `internal/container` (orchestration), `proto/`
(vendored contract + PIN), `vz.entitlements`, Justfile recipes
(`build`, `proto`, `test`). protoc/protoc-gen-go/protoc-gen-go-grpc are
aqua-pinned.

Two runtime-unverified assumptions to watch on first live run (both
fail loud, both have fallbacks): vminitd `Copy(COPY_IN, is_archive)`
extraction fidelity, and `ConfigureDns/Hosts` `location` semantics
(rootfs dir vs file path).

One deliberate simplification vs the original plan: the rootfs is
**tmpfs + vminitd's own `Copy(COPY_IN, is_archive)` extraction** of the
host-flattened tar.gz — full metadata fidelity with zero extra guest
binaries (no imager, no mkfs, no ext4 writer). RAM-backed rootfs is the
accepted cost. The persistent ext4 path — needed only for warm buildkit
caches — is now implemented, but the ext4 writer lives on the **host**
(pure-Go go-diskfs), not in the guest, so the initfs stays minimal (it
has no `mkfs`). See the persistent-cache note in the status block above.

Library facts verified live 2026-07-08 (pkg.go.dev for `Code-Hex/vz`
v3.7.1 and `gvisor-tap-vsock`); guest facts verified against the
`apple/containerization` checkout and the v1 spike, which proved
end-to-end: cctl → microVM → buildkitd → host `buildctl` over TCP, with
the one blocker (capabilities) root-caused and patched.

### What we reuse vs own

| Piece | Source | Why |
|---|---|---|
| **Guest kernel** (`kernel-arm64`) | apple/containerization `kernel/` config, built by our own pipeline (v1 `build.sh` already does this via a Kata-booted build VM — no apple/container needed) | VZ-tuned, everything `=y`, validated in v1 |
| **Guest init** (`initfs.ext4` = `vminitd` + `vmexec`) | apple/containerization, cross-built with the Swift Static Linux SDK (v1 `build.sh` does this) | the hard guest-agent work: PID-1, gRPC-over-vsock, mounts, cgroups, netlink, stdio |
| **The proto** (`SandboxContext.proto`) | vendored from the same containerization ref as the initfs — **they version together** | the host↔guest contract; compiles to Go with protoc |
| **Everything host-side** | **ours, pure Go** | the whole point |

Swift/Xcode does **not** disappear — it moves into the *artifact factory*
(the CI job that builds kernel + initfs per pinned upstream ref). The
runtime binary is pure Go + Code-Hex/vz (CGO for the framework, no Swift).

### Architecture

```
host (macOS, one Go binary: ossein)                      guest (per-container microVM)
┌──────────────────────────────────────────┐            ┌───────────────────────────┐
│ image: go-containerregistry (pull,       │            │ kernel: kernel-arm64     │
│   flatten via mutate.Extract)            │  VZ boot   │ init:   vminitd (PID 1)   │
│ vm:    Code-Hex/vz v3.7.x                │ ─────────► │                           │
│   virtio-blk  (rootfs.ext4, cache disk)  │            │ gRPC over vsock :1024     │
│   virtio-fs   (host dir mounts)          │ ◄────────► │   create/start/exec/wait  │
│   vsock       VirtioSocketDevice.Connect │  net.Conn  │   stdio streams, signals  │
│ net:   gvisor-tap-vsock in-process       │            │   netlink IP config       │
│   FileHandleNetworkDeviceAttachment      │            │                           │
│   (socketpair fd) + AcceptVfkit          │            │ container process         │
│   Dial()/DialContextTCP() from host code │            │   (e.g. buildkitd)        │
│ expose: host unix/tcp listener ──proxy──►│            │                           │
└──────────────────────────────────────────┘            └───────────────────────────┘
```

Key verified capabilities this rests on:
- `vz.VirtioSocketDevice.Connect(port) → *VirtioSocketConnection` (a
  `net.Conn`) — **host→guest vsock dialing from Go, in-process**. This is
  what makes gRPC-to-vminitd (and any socket forwarding) pure Go.
- `vz.FileHandleNetworkDeviceAttachment` + gvisor-tap-vsock
  `AcceptVfkit(ctx, conn)` — the podman-machine/vfkit usermode network,
  embedded as a **library in our process** (no gvproxy subprocess).
- `VirtualNetwork.Dial()/DialContextTCP()` — host code dials guest
  TCP through the in-process stack → a host `unix://` listener proxying to
  guest buildkitd is ~20 lines. **`BUILDKIT_HOST=unix://…` with zero guest
  changes.** (vmnet NAT stays as a fallback; v1 proved host→guest TCP.)
- `vz` virtio-fs (`NewVirtioFileSystemDeviceConfiguration`) for host dir
  mounts; Rosetta via vz's `LinuxRosettaDirectoryShare` (what vfkit uses —
  confirm exact symbol at pin time).

### The rootfs problem (decided approach)

Go cannot write ext4; a macOS-dir-over-virtiofs rootfs loses uid/setuid/
xattr fidelity (breaks rootless buildkit, real distro images). Solution —
**materialize inside the guest, where we're root and it's native**:

1. Host: pull + flatten image to a tarball stream (`mutate.Extract`);
   create a **blank raw disk** (sparse file).
2. Boot the **imaging step** on kernel+initfs; attach the blank disk;
   virtiofs-share a dir containing our **`imager`** — a static Go
   linux/arm64 helper (`CGO_ENABLED=0` cross-build, trivial).
3. vminitd execs `imager`: `mke2fs` the disk *(see open Q3)*, mount,
   apply the tar **with whiteouts and full metadata** (containerd's
   `archive.Apply` — battle-tested), fsync, exit.
4. Host caches the result: **image digest → rootfs.ext4** in a content
   store; imaging cost is once per image, subsequent runs attach a
   CoW clone (APFS `clonefile`) of the cached ext4.

The persistent buildkit cache disk is the same trick minus the tar: blank
disk, `mke2fs` once in-guest, reattach forever.

### Capabilities (the v1 lesson)

vminitd's create RPC carries the OCI process config, including
capabilities — cctl just never exposed it (v1 EPERM). ossein sets the cap
set explicitly per run: default = OCI default; `--privileged` = full set.
Privileged-in-a-throwaway-microVM is the model (isolation at the VM
boundary), which is how buildkitd runs.

### Milestones

Ordered risk-first; each has a hard acceptance test.

**M0 — artifact factory + scaffolding**
- Extract v1 `build.sh` into a pinned pipeline producing three artifacts:
  `kernel-arm64`, `initfs.ext4`, `SandboxContext.proto` (single upstream
  ref), plus checksums. Publish as repo releases (aqua-consumable later).
- Go module scaffolding, `just` recipes, protoc codegen (pinned via aqua),
  vz pinned at v3.7.x, entitlement file + codesign step in the build
  recipe (`com.apple.security.virtualization`, ad-hoc locally).
- ✅ *Accept:* `just build` emits a signed `ossein` binary; artifacts
  reproducible from the pinned ref.

**M1 — boot + handshake (kills the biggest unknown)**
- `ossein` boots kernel+initfs via vz (LockOSThread, serial console to a
  log file for debugging), dials vsock :1024, completes a vminitd gRPC
  call (whatever the proto's cheapest RPC is) and clean-shuts-down.
- ✅ *Accept:* `ossein doctor` boots, handshakes, tears down, leaves zero
  state behind — repeatedly.

**M2 — imaging pipeline**
- Image pull/flatten (go-containerregistry), blank-disk creation, the
  `imager` guest helper, digest-keyed ext4 cache + APFS clone.
- ✅ *Accept:* fidelity test — image a rootfs from `moby/buildkit:rootless`
  and assert in-guest: correct multi-uid ownership, setuid on
  `newuidmap`, `security.capability` xattr survives on a known file.

**M3 — run a container (buildkit parity with v1)**
- Full create/start over vminitd gRPC: rootfs (cloned ext4), mounts
  (virtio-fs), caps, env/cwd/user, stdio streaming, exit codes, signals.
- Networking: embedded gvisor-tap-vsock; static guest IP pushed via
  vminitd's netlink config (no DHCP client dependency in images);
  host-side `unix://` proxy via `VirtualNetwork.Dial`.
- `ossein buildkit` = long-lived buildkitd VM + cache disk + prints
  `BUILDKIT_HOST=unix://…`; supervised lifecycle; **cleanup that actually
  runs** (defer + signal handler + `ossein gc` sweep — cctl's gap).
- ✅ *Accept:* the v1 smoke, better: `buildctl build` of a real Dockerfile
  over the unix socket; kill -9 the daemon → `ossein gc` leaves no orphans.

**M4 — general `ossein run`**
- Arbitrary OCI images: TTY/raw-mode stdio, `--mount`, `--publish`
  (gvproxy port forward), `--rosetta` (share + binfmt registration),
  resource flags. State dir with unique IDs (XDG), `list`/`stop`/`rm`.
- ✅ *Accept:* `ossein run -it alpine sh` interactive; `debian` boots with
  working apt (fidelity); amd64 image runs under Rosetta.

**M5 — doctrine integration**
- aqua packaging (binary + artifacts + checksums/attestations), signing
  story for distribution (open Q1), Renovate on the containerization ref,
  kernel/initfs bump ritual, LIMEN-VIRT.md update, retire v1 to reference.
- ✅ *Accept:* a sibling repo consumes ossein via aqua and builds an image
  in CI with no Docker/Lima/apple-container present.

### Open questions

1. **Distribution signing.** Ad-hoc signatures don't travel. Options:
   Developer ID cert in CI, or sign-on-install ritual (limen-install).
   Decide before M5; ad-hoc suffices through M4.
2. **vz coverage of macOS 26 APIs.** NAT/file-handle/vsock/virtiofs are
   verified; the newer vmnet APIs may not be wrapped. Mitigation: we
   don't need them (gvisor-tap-vsock path), NAT as fallback.
3. **`mke2fs` sourcing.** Host-side (brew/aqua `e2fsprogs` makes the
   *empty* fs on macOS — userspace, image-file only) vs a static
   linux/arm64 `mke2fs` in the guest-tools share. Prefer host-side if
   e2fsprogs pins cleanly; else one-time static build via the v1 path.
4. **Proto/initfs skew.** Vendor proto + initfs from one ref and assert a
   version handshake at M1 so drift fails loud.
5. **vminitd replacement (vNext, not this plan).** A Go static init
   (AF_VSOCK is native in the Linux guest) would remove Swift from the
   artifact factory entirely and give us the proto. Only after M4 parity.

### Non-goals

- No daemon, ever. `ossein` processes own their VMs; nothing shared, no
  root, no `/usr/local`.
- Pods / multi-container VMs (containerization's LinuxPod) are **not built
  now** — one container, one VM — but deliberately **not foreclosed**: the
  full `vmexec` port keeps per-container namespaces/cgroups/caps (the pod
  primitives), the proto is multi-container-aware (`containerID` per process),
  and the guest agent stays stateless-per-path (no single-container globals).
- No macOS/Windows guests — LIMEN-VIRT routes those to UTM.
- No x86 hosts; arm64 only (kernel artifact is arm64; x86_64 kernel
  config exists upstream if ever needed).
